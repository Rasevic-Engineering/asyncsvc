# Connecting to Cloud SQL from your machine

The app's Postgres database is a Cloud SQL instance (PostgreSQL 16). It has a public IP with **no authorized networks**, so you can't connect to it directly. Instead, the **Cloud SQL Auth Proxy** opens an encrypted tunnel from your machine, authorized by your gcloud login.

> **This is the live database.** The `app` user can read and write everything. Prefer read-only sessions (see [Staying read-only](#staying-read-only)) and be careful with `UPDATE` and `DELETE`.

## Prerequisites (one-time)

```bash
brew install cloud-sql-proxy libpq     # proxy + psql client
brew link --force libpq                # put psql on your PATH
gcloud auth login                      # your Google account
gcloud auth application-default login  # credentials the proxy uses
```

Your account needs the **Cloud SQL Client** role on the project. Project owners already have it.

## 1. Find the instance

The connection name is a Pulumi stack output:

```bash
cd infra && pulumi stack output dbConnectionName
# asyncsvc-dev:us-central1:postgres-1923e34
```

Or ask gcloud:

```bash
gcloud sql instances list --project asyncsvc-dev --format="value(connectionName)"
```

## 2. Start the proxy

Run this in its own terminal tab and leave it running. It listens on `127.0.0.1:5433`, which keeps 5432 free for the local docker-compose Postgres:

```bash
cloud-sql-proxy asyncsvc-dev:us-central1:postgres-1923e34 --port 5433
```

You should see `The proxy has started successfully and is ready for new connections!`. Stop it with **Ctrl+C** when you're done.

## 3. Put the database password in an environment variable

The password is generated by Pulumi and stored in Secret Manager (`asyncsvc-db-password`). Load it straight into `PGPASSWORD`, which `psql` reads automatically, so it never appears on screen or in your shell history:

```bash
export PGPASSWORD="$(gcloud secrets versions access latest --secret asyncsvc-db-password --project asyncsvc-dev)"
```

Check that it's set, without printing it:

```bash
test -n "$PGPASSWORD" && echo "PGPASSWORD is set (${#PGPASSWORD} chars)"
```

Clear it when you're done:

```bash
unset PGPASSWORD
```

## 4. Connect

In a second tab, in the same shell where you exported `PGPASSWORD`:

```bash
psql "host=127.0.0.1 port=5433 user=app dbname=app"
```

Run a single query without an interactive session:

```bash
psql "host=127.0.0.1 port=5433 user=app dbname=app" -c "SELECT status, count(*) FROM reports GROUP BY 1"
```

GUI clients (TablePlus, DBeaver, DataGrip, pgAdmin) work the same way: host `127.0.0.1`, port `5433`, user `app`, database `app`, and the password from step 3, with SSL off, because the proxy already encrypts the connection.

### Staying read-only

To make accidental writes impossible for a whole session:

```bash
PGOPTIONS="-c default_transaction_read_only=on" psql "host=127.0.0.1 port=5433 user=app dbname=app"
```

Or, inside `psql`, wrap your work in a read-only transaction:

```sql
BEGIN READ ONLY;
-- queries...
COMMIT;
```

## What's in the database

| Table | Contents |
|---|---|
| `reports` | One row per report request: kind, date range, status, owner, file location, formats, row count, errors, timings |
| `outbox` | Pub/Sub messages written in the same transaction as the change that caused them, then published by the relay |
| `email_deliveries` | Dedupe log so a retried message never sends the same email twice |
| `schema_migrations` | Which migrations in `app/internal/db/migrations` have been applied |

User accounts live in Firebase Auth, report files in Cloud Storage, analytics events and message activity history in BigQuery, and the live Activity feed in Firestore. None of those are in Postgres.

## Sample queries

Useful `psql` commands: `\dt` lists tables, `\d reports` describes a table, `\x auto` switches to expanded output for wide rows, `\timing on` shows query time, and `\q` quits.

### Reports

```sql
-- Reports by status
SELECT status, count(*) FROM reports GROUP BY status ORDER BY count(*) DESC;

-- 20 most recent reports
SELECT id, kind, params->>'from' AS "from", params->>'to' AS "to (exclusive)",
       status, owner_email, row_count, formats, created_at
FROM reports
ORDER BY created_at DESC
LIMIT 20;

-- Failed reports and why
SELECT id, kind, owner_email, attempts, error, completed_at
FROM reports
WHERE status = 'failed'
ORDER BY completed_at DESC
LIMIT 20;

-- Reports retrying right now (pending again after a failed attempt)
SELECT id, kind, attempts, error, started_at
FROM reports
WHERE status = 'pending' AND attempts > 0;

-- Possibly stuck: running for more than 15 minutes
SELECT id, kind, attempts, started_at, now() - started_at AS running_for
FROM reports
WHERE status = 'running' AND started_at < now() - interval '15 minutes';

-- Generation time per report kind (last 7 days)
SELECT kind,
       count(*)                                                         AS reports,
       round(avg(extract(epoch FROM completed_at - started_at))::numeric, 1) AS avg_seconds,
       round(max(extract(epoch FROM completed_at - started_at))::numeric, 1) AS max_seconds,
       sum(row_count)                                                   AS total_rows
FROM reports
WHERE status = 'ready' AND completed_at > now() - interval '7 days'
GROUP BY kind
ORDER BY reports DESC;

-- Reports per user
SELECT coalesce(owner_email, '(created before auth)') AS owner, count(*) AS reports,
       count(*) FILTER (WHERE status = 'failed') AS failed, max(created_at) AS last_request
FROM reports
GROUP BY 1
ORDER BY reports DESC;

-- Where a report's files are in Cloud Storage
SELECT id, file_key, formats FROM reports WHERE id = '<report-id>';
```

### Outbox (Pub/Sub messages)

```sql
-- Backlog: messages not yet published to Pub/Sub (should normally be 0)
SELECT topic, count(*) AS unpublished, min(created_at) AS oldest
FROM outbox
WHERE published_at IS NULL
GROUP BY topic;

-- Messages that failed to publish, and the last error
SELECT id, topic, attempts, last_error, created_at
FROM outbox
WHERE published_at IS NULL AND attempts > 0
ORDER BY created_at;

-- Publish latency: time from commit to Pub/Sub (last hour)
SELECT topic,
       count(*) AS messages,
       round(avg(extract(epoch FROM published_at - created_at) * 1000)) AS avg_ms,
       round(max(extract(epoch FROM published_at - created_at) * 1000)) AS max_ms
FROM outbox
WHERE published_at > now() - interval '1 hour'
GROUP BY topic;

-- Recent messages with their payloads
SELECT topic, payload, attributes, created_at, published_at
FROM outbox
ORDER BY created_at DESC
LIMIT 10;
```

### Emails

```sql
-- Emails by template and status
SELECT template, status, count(*) FROM email_deliveries GROUP BY 1, 2 ORDER BY 1, 2;

-- Most recent emails
SELECT recipient, template, status, created_at, sent_at
FROM email_deliveries
ORDER BY created_at DESC
LIMIT 20;

-- Stuck in "sending" (the worker crashed between sending and recording)
SELECT message_id, recipient, template, created_at
FROM email_deliveries
WHERE status = 'sending' AND created_at < now() - interval '10 minutes';
```

### Schema

```sql
-- Applied migrations
SELECT version, applied_at FROM schema_migrations ORDER BY version;

-- Table sizes
SELECT relname AS table, pg_size_pretty(pg_total_relation_size(relid)) AS size, n_live_tup AS rows
FROM pg_stat_user_tables
ORDER BY pg_total_relation_size(relid) DESC;
```

## Local database (docker-compose)

The local stack's Postgres needs no proxy or secret:

```bash
cd app && docker compose exec postgres psql -U app
```

Or from your Mac:

```bash
psql "postgres://app:app@localhost:5432/app"
```

## Troubleshooting

| Problem | Fix |
|---|---|
| Proxy: `failed to get instance` / `403` | Your account lacks **Cloud SQL Client**, or the connection name is wrong. Check with `gcloud sql instances list` |
| Proxy: `could not find default credentials` | Run `gcloud auth application-default login` |
| `psql: command not found` | `brew link --force libpq` |
| `password authentication failed` | `PGPASSWORD` isn't set in *this* shell; re-run the export from step 3 |
| `connection refused` on 5433 | The proxy isn't running, or it's on another port |
| `address already in use` | Something else is using 5433; pick another port, e.g. `--port 5434`, and use it in `psql` |
